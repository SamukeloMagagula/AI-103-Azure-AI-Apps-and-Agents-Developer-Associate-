1Install the extension & sign in

Objective → Plan and manage an Azure AI solution · Design Azure infrastructure for AI apps

Install

  1. Open VS Code → Extensions (Ctrl+Shift+X).
  2. Search Microsoft Foundry (publisher ms-azuretools) → Install.
  3. Install dependencies: Azure Resources, Python.
  4. Reload the window so the Foundry Activity Bar icon appears.

Sign in — use Device Code, not the browser flow

The default browser redirect breaks silently when loopback is blocked (corporate firewalls, non-default browser profiles). Use Device Code from the start:

  1. Ctrl+Shift+P → Azure: Sign In with Device Code.
  2. Copy the 9-character code from the notification.
  3. Open microsoft.com/devicelogin, paste the code, authenticate.
  4. Wait ~15 seconds. Status bar bottom-left should show your email.
⬢ AI-103 fact For keyless auth, code uses DefaultAzureCredential(). Token scope for Azure OpenAI = https://cognitiveservices.azure.com/.default, for the Foundry project = https://ai.azure.com/.default. Required roles: Cognitive Services OpenAI User, Azure AI Developer, Search Index Data Reader.

2Pick the tenant, subscription & register providers

Objective → Choose appropriate deployment options · Design Azure infrastructure
  1. Ctrl+Shift+P → Azure: Select Tenant (skip if only one).
  2. Azure: Select Subscriptions → tick the sub holding your resource group.
  3. In the Azure portal: open the subscription → Resource providers → ensure these are Registered:
    • Microsoft.CognitiveServices (Azure OpenAI + other AI services)
    • Microsoft.MachineLearningServices (Foundry projects + agents)
    • Microsoft.Search (AI Search)
    • Microsoft.Storage (RAG ingestion)
!A new subscription will refuse Microsoft.CognitiveServices deployments with a 409 until you register the provider. The exam loves this trap.

5Responses API — the current protocol

Objective → Build generative applications by using Foundry · Deploy and consume LLMs

Open Foundry → Playground to call the Responses API without writing code. Export → Python to copy the exact snippet.

from openai import AzureOpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

token_provider = get_bearer_token_provider(
    DefaultAzureCredential(),
    "https://cognitiveservices.azure.com/.default")

client = AzureOpenAI(
    azure_endpoint    = "https://<aoai>.openai.azure.com/",
    api_version       = "2025-03-01-preview",
    azure_ad_token_provider = token_provider)

r = client.responses.create(
    model        = "gpt-4o-mini",          # DEPLOYMENT name
    instructions = "You are a terse Azure tutor.",
    input        = "Explain embeddings in one sentence.")
print(r.output_text)

6Build an agent with the Agent Framework

Objective → Build agents by using Foundry: roles, goals, conversation tracking, tool schemas (30-35% section)

Open Foundry → Agents → + New agent. The designer writes agents/<name>.agent.yaml which you check into git. The three core objects you must memorise:

ObjectPurposeCreation call
AgentPersona + model + tools + instructions. Reusable.agents.create_agent(...)
ThreadConversation memory. Lives independently of an agent.agents.threads.create()
RunOne execution of an agent against a thread.agents.runs.create_and_process(thread_id, agent_id)

Run lifecycle (every state is a possible exam question)

queued → in_progress ─┬─► completed      (final message on the thread)
                      ├─► requires_action (tool call needs your output)
                      ├─► failed         (error in agent.last_error)
                      ├─► cancelled      (you called runs.cancel)
                      └─► expired        (exceeded max_completion_tokens)

Multi-agent orchestration

For the exam, know that a lead agent decomposes a task, delegates subtasks to specialist agents, then aggregates on a shared thread. Memory lives on the thread, not the agent — this is why specialists can see each other's work.

Approval flow (semi-autonomous agents)

Mark any dangerous tool with requires_approval: true. The run halts at requires_action until a human (or policy engine) posts an approve or reject back via runs.submit_tool_outputs(). Use this for send_email, run_sql, execute_payment.

RAG — two patterns the exam contrasts

Server-side (On Your Data) — Foundry does retrieval:

client.chat.completions.create(
    model = deployment,
    messages = [...],
    extra_body = {"data_sources": [{
        "type": "azure_search",
        "parameters": {
            "endpoint": "https://<search>.search.windows.net",
            "index_name": "docs-index",
            "authentication": {"type": "system_assigned_managed_identity"},
            "embedding_dependency": {
                "type": "deployment_name",
                "deployment_name": "text-embedding-3-small"},
            "query_type": "vector_semantic_hybrid"}}]})

Client-side — you orchestrate:

# 1. embed query   2. search index   3. stuff context   4. responses.create

AI Search index essentials (exam-ready)

Field attributeWhat it enables
searchableFull-text matches on this field
filterable$filter=category eq 'ai'
sortable$orderby=price desc
facetableAggregate counts for faceted navigation
retrievableReturned in search results (false = filter-only)
keyUnique id (exactly one field per index)

Vector field type: Collection(Edm.Single) with dimensions and vectorSearchProfile. Hybrid search = BM25 + vector scores fused via RRF (Reciprocal Rank Fusion). Semantic ranker needs a semanticConfiguration and returns @search.reranker_score, captions, answers.

    "role": "user",
    "content": [
        {"type": "input_text",  "text": "Produce alt-text under 125 chars."},
        {"type": "input_image", "image_url": "https://..."}]}])

Content Understanding — unified extractor for doc / image / video / audio

CU replaces Document Intelligence on the AI-103 skills list. One tool, four analyzer kinds:

Analyzer kindInputOutputs
documentPDF / imageOCR text, layout, fields, tables, markdown
imageJPG / PNGCaptions, tags, embedded text, objects
videoMP4Scene segments, transcript, visual summary
audioWAV / MP3Transcript, diarization, sentiment

Modes: standard (single-task, fast) · pro (multi-step reasoning, slower, higher quality). Prebuilts to recognise: prebuilt-documentAnalyzer, invoice-markdown, receipt, businessCard, idDocument.

⬢AI-103 factIndirect prompt-injection attacks hide instructions inside document OCR or image text. Always run untrusted content through Prompt Shield (Content Safety) before passing it to an LLM.

9Text analysis & Speech

Objective → Implement text analysis solutions · Implement speech solutions

Structured text extraction with the Responses API

AI-103 prefers LLM-prompted extraction over the classic Language service. Force a schema:

SCHEMA = {
    "type": "json_schema",
    "json_schema": {
        "name": "ticket",
        "strict": True,
        "schema": {
            "type": "object",
            "properties": {
                "sentiment":  {"type":"string","enum":["positive","neutral","negative"]},
                "intent":     {"type":"string"},
                "entities":   {"type":"array","items":{"type":"string"}},
                "summary":    {"type":"string"}},
            "required": ["sentiment","intent","summary"]}}}

client.responses.create(model=dep, input=text, response_format=SCHEMA)

Translator — as a Foundry Tool or raw REST

POST https://api.cognitive.microsofttranslator.com/translate?api-version=3.0&to=af&to=zu
Headers: Ocp-Apim-Subscription-Key, Ocp-Apim-Subscription-Region
Body:    [{"text": "Hello"}]
!Ocp-Apim-Subscription-Region is mandatory alongside the key. Omitting it returns 401. Classic exam trap.

Speech — STT, TTS, custom speech

import azure.cognitiveservices.speech as speechsdk
cfg = speechsdk.SpeechConfig(subscription=key, region=region)
cfg.speech_recognition_language = "en-US"

# STT
reco = speechsdk.SpeechRecognizer(speech_config=cfg,
            audio_config=speechsdk.audio.AudioConfig(filename="in.wav"))
reco.recognize_once_async().get()

# TTS (neural voice)
cfg.speech_synthesis_voice_name = "en-US-AvaNeural"
synth = speechsdk.SpeechSynthesizer(speech_config=cfg)
synth.speak_text_async("Hello from Foundry").get()

# Custom Speech — point at your deployment
cfg.endpoint_id = "<deployment-guid>"

For voice agents, prefer the Realtime API (gpt-4o-realtime) over the STT → chat → TTS hop — one WebSocket, no intermediate text latency.

Content Safety categories

Each of Hate / Sexual / SelfHarm / Violence gets a severity 0 (safe) · 2 (low) · 4 (medium) · 6 (high) — the default FourSeverityLevels scale. Also available: EightSeverityLevels (0/1/2/3/4/5/6/7).

Prompt Shield — the two attack types

  • User prompt attacks — jailbreaks like "Ignore all previous instructions."
  • Document attacks — instructions smuggled in ingested documents (indirect prompt injection).

Common gotchas

  • model= is always the deployment name, never the model id.
  • Translator requires both Ocp-Apim-Subscription-Key and Ocp-Apim-Subscription-Region.
  • Hybrid search merges BM25 + vector via RRF.
  • Vector field type = Collection(Edm.Single).
  • Content Safety default severities = 0, 2, 4, 6.
  • finish_reason="content_filter" → safety block, not an error.
  • Agent memory lives on the thread, not the agent.
  • Run state requires_action → you must call submit_tool_outputs.
  • Responses API is the current path; Chat Completions is legacy but still tested.
  • 429 responses → check TPM quota per region; mitigate with PTU, multi-region, or Batch SKU.

12Troubleshooting the toolkit itself

"You are not signed in to an Azure account" loops in the logs
  1. Prefer Device Code: Azure: Sign In with Device Code.
  2. After auth, run Azure: Select Tenant then Azure: Select Subscriptions.
  3. If still unsigned: close VS Code, delete %USERPROFILE%\.Azure\ and %APPDATA%\Code\User\globalStorage\ms-vscode.azure-account\, reopen.
  4. Confirm you installed Azure Resources (not the deprecated Azure Account).
401 invalid_api_key pointing at platform.openai.com

Your model is registered under the OpenAI provider instead of Azure OpenAI. Azure keys don't start with sk- and public OpenAI rejects them.

  1. Rotate the leaked key: Portal → the Azure OpenAI resource → Keys and Endpoint → Regenerate Key1 + Key2.
  2. In Foundry tree view, right-click the OpenAI/… model → Remove.
  3. + Add Model → Azure OpenAI, pick subscription → resource → deployment. Don't paste a key.
Deployment picker is empty
  1. Open the Azure OpenAI resource in Azure AI Foundry portal → Model deployments → + Deploy model.
  2. Pick the model, name it, choose SKU (GlobalStandard is safest), set TPM capacity → Deploy.
  3. Return to VS Code and re-run Add Model.
Response 429 (ratelimited)
  1. Check TPM used vs quota in the Monitoring pane.
  2. Raise TPM for the deployment (per region; check regional caps in the portal).
  3. Add a second deployment in a different region and load-balance client-side.
  4. For predictable latency, switch to ProvisionedManaged (PTU).
  5. Respect Retry-After / x-ms-retry-after-ms headers in your client.
Private endpoint blocks the extension

If the AOAI resource has public network access disabled, VS Code on a laptop outside the VNet can't reach it. Either:

  • Connect over the corporate VPN / Azure Bastion and keep public access off, or
  • Temporarily enable Selected networks with your public IP, run the extension, then re-lock.
