2How good do you need to be at Foundry before you sit?

Microsoft Foundry is referenced in every single section — it is the connective tissue of AI-103. Use this 0-5 self-assessment before you book the exam. Aim for Level 4 minimum. Level 3 passes only with some luck on question mix.

0Unaware

Has not opened Foundry

Only knows Azure OpenAI Studio exists. Cannot describe a Foundry project. Weeks of study away.

1Browsed

Can explore the UI

Can log in, see the model catalog, deploy a model. Doesn't yet connect code to it. Not ready. Spend time on hands-on coding.

2Chatty

Can call the Responses API

Runs chat completions with Python + deployment name. Understands keys vs managed identity. Does NOT yet grasp agents or RAG wiring. Still not ready.

3Agentic

Can build a single agent with tools

Creates an agent with azure-ai-agents, attaches file_search + a function tool, handles the requires_action loop. Can wire AI Search as a data source. Borderline pass — still risky.

4Fluent

Can orchestrate multi-agent + evaluate + deploy

Builds multi-agent handoffs on a shared thread. Picks the right tool for each job (CU vs file_search vs azure_ai_search). Runs evaluators (GroundednessEvaluator etc.). Configures Prompt Shield and Content Safety. Target level before writing.

5Production

Ship-ready engineer

Keyless auth with managed identity everywhere, private endpoints, PTU vs GlobalStandard chosen deliberately, CI with foundry eval gates, Log Analytics + Azure Monitor wired. Comfortable pass; will also crack scenario questions.

Quick self-test — can you answer YES to all of these?

  • I can create a Foundry project (not just a resource) and explain what sits inside it.
  • I can distinguish a model id from a deployment name and know which goes in my code.
  • Given a task, I can pick between function, file_search, azure_ai_search, content_understanding, openapi and code_interpreter tools.
  • I can explain the Agent / Thread / Run triad in one sentence each.
  • I can describe the run-state lifecycle including when requires_action fires.
  • I can configure "On Your Data" RAG via the data_sources extension body.
  • I can name three evaluators and what they detect.
  • I can name three RBAC roles and which resource they attach to.

Seven YES answers = Level 4. Six or fewer = schedule the exam a week later and drill the weak spots.

4Plan and manage an Azure AI solution — 25-30%

What Microsoft Learn says you must do

  • Choose appropriate Foundry services for generative AI and agents (LLM vs SLM vs multimodal vs reasoning).
  • Set up AI solutions in Foundry — infrastructure, deployments, CI/CD.
  • Manage, monitor, and secure AI systems — quotas, scaling, managed identity, keyless credentials, private networking.
  • Implement responsible AI across generative and agentic systems — safety filters, evaluators, audit, oversight modes.

Exercises

Exercise 1.1Difficulty ★☆☆

Open the Azure portal, create a Foundry project (not just a Cognitive Services resource), deploy gpt-4o-mini at GlobalStandard, 10k TPM. Note the deployment name — you'll use it in every later exercise.

Exercise 1.2Difficulty ★★☆

Register a system-assigned managed identity on a VM or App Service, give it the Cognitive Services OpenAI User role on your AOAI resource, then call the Responses API from Python with DefaultAzureCredential() — no keys in code or env.

Exercise 1.3Difficulty ★★☆

Enable Diagnostic Settings on the AOAI resource, send RequestResponse + Trace to a Log Analytics workspace. Run 5 chat requests, then write a Kusto query that returns prompts + completions with latency.

Exercise 1.4Difficulty ★★★

Deliberately trigger a 429 by looping requests. Add exponential backoff that respects the x-ms-retry-after-ms header. Then deploy the same model in a second region and round-robin between the two deployments.

Exercise 1.5Difficulty ★★★

Tighten the deployment's content filter to block severity ≥ 2 for Violence. Send a borderline prompt and confirm the response's finish_reason is content_filter.

5Implement generative AI and agentic solutions — 30-35% (BIGGEST)

What Microsoft Learn says you must do

  • Build generative applications by using Foundry (Responses API, RAG, workflows, evaluation).
  • Build agents by using Foundry — roles, goals, tool schemas, function calling, memory, multi-agent orchestration, approval flows.
  • Optimise and operationalise — prompt engineering, model reflection, tracing, token analytics.

Exercises

Exercise 2.1Difficulty ★☆☆

Write a 20-line Python script that calls client.responses.create(...) with an instruction, a user input, and response_format={"type":"json_schema","strict":true,...}. Verify the output parses with json.loads().

Exercise 2.2Difficulty ★★☆

Create an agent with file_search. Upload three PDFs to its vector store. Ask a question that only one PDF can answer and verify the citation in the response.

Exercise 2.3Difficulty ★★★

Add a function tool get_order_status(order_id: str) -> dict. Handle the requires_action state, submit the tool output, let the run complete. Then mark the tool requires_approval: true and add a CLI prompt that approves or rejects.

Exercise 2.4Difficulty ★★★

Build three agents — lead, researcher, writer — on a shared thread. The lead decomposes a task, delegates to researcher, then writer, then aggregates. Print the trace.

Exercise 2.5Difficulty ★★★

Create golden.jsonl with 10 (query, expected answer, context) rows. Run evaluate() with GroundednessEvaluator, RelevanceEvaluator, FluencyEvaluator, ContentSafetyEvaluator. Fail the build if groundedness < 0.7.

9Exam-day strategy

Question patterns to expect

  • Scenario → service pick: "A customer needs X; which Azure AI service fits?" Memorise the decision table in Day 1.
  • Code-completion: drag-and-drop the right SDK method or REST verb into a snippet. Learn the exact method names (create_and_process, submit_tool_outputs).
  • YAML / JSON config: pick the correct field name (query_type, vectorSearchProfile, analyzer_id).
  • Troubleshooting: "Users get 429 — what do you do?" Three correct answers usually: raise TPM, add a region, switch to PTU.
  • Case study: read a page of context, answer 5-8 linked questions. Skim the questions first so you know what to look for.

Timing

120 minutes / ~50 questions = ~2 minutes per question. Flag long case studies, do multiple-choice first, come back. Leave 10 minutes at the end for review.

Dirty tricks to notice

  • Question asks for "the fewest changes to meet the requirement" — avoid the over-engineered answer.
  • Two answers look right; one is deprecated (Chat Completions where Responses now applies, Form Recognizer vs Content Understanding, Azure Account vs Azure Resources extension).
  • "System-assigned" vs "user-assigned" managed identity — read carefully.
  • "Region" trap — Translator needs Ocp-Apim-Subscription-Region; forgetting it is a popular wrong answer.

11Pre-flight checklist (24h before)

  • ☐ Scored ≥ 750 on the official Microsoft Practice Assessment at least twice.
  • ☐ Can describe every item in the Chapter Index above without peeking.
  • ☐ Can write, from memory, a 30-line agent with a function tool.
  • ☐ Can name 5 evaluators and what each detects.
  • ☐ Can explain the difference between Chat Completions and Responses in 2 sentences.
  • ☐ Know the Translator region-header trap.
  • ☐ ID + second ID ready, proctoring room checked, laptop + webcam + mic tested.
  • ☐ 8 hours sleep. Yes, really — scenario questions get harder when tired.
