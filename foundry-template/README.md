# Foundry scaffold — Agent Framework template

A minimal Microsoft Foundry agent scaffold generated by the **Microsoft
Foundry** extension for Visual Studio Code. This branch (`foundry-template`)
is kept intentionally separate from `main` — `main` holds the AI-103
study kit (practice scripts + HTML guides); this branch holds the live
runnable template you deploy to Azure.

## What it is

A single-agent server using:

- **Microsoft Agent Framework** (`agent-framework-foundry`)
- **Foundry hosting layer** (`agent-framework-foundry-hosting`) — exposes the
  agent over the Responses API on `:8088`
- **Azure Identity** (`DefaultAzureCredential`) — no API keys in code
- **uv** for dependency management, **Docker** for packaging

## Prerequisites

- Python 3.13
- [uv](https://docs.astral.sh/uv/) 0.11+
- An Azure Foundry project with at least one chat model deployment
- The `Cognitive Services OpenAI User` role on your Azure OpenAI resource
  (or `Azure AI Developer` on the Foundry project)

## Configure

Copy `.env.example` to `.env` and fill in two values:

```
FOUNDRY_PROJECT_ENDPOINT=https://<your-project>.services.ai.azure.com/api/projects/<your-project>
AZURE_AI_MODEL_DEPLOYMENT_NAME=<your-deployment-name>
```

The deployment name is the one you typed when you deployed the model in
the Foundry portal — **not** the model id (`gpt-4o-mini` etc.).

## Run locally

```powershell
uv sync
az login                      # DefaultAzureCredential uses this token
uv run python main.py
```

The server listens on `http://localhost:8088`. Send it a Responses API
request to trigger the agent.

## Run in Docker

```powershell
docker build -t foundry-agent .
docker run --rm -p 8088:8088 --env-file .env foundry-agent
```

## Deploy to Azure

```powershell
azd up
```

Uses `azure.yaml` if present; otherwise provision Container Apps / App
Service manually and point it at this image.

## Security notes

- `.env` is gitignored — never commit real endpoints or keys.
- The container runs as a non-root user (`appuser`) with a HEALTHCHECK.
- Authentication is keyless via managed identity in Azure; locally it
  falls back to your `az login` token.
